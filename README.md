# Notes

A small full-stack notes app: create, edit and delete notes, archive/unarchive
them, tag them with categories and filter by category. Access is protected by a
simple username/password login that issues a JWT.

The frontend and backend are two independent apps that talk to each other only
through a REST API.

| Part     | Stack                                                          | Folder      |
| -------- | -------------------------------------------------------------- | ----------- |
| Frontend | React + TypeScript (Vite), plain CSS                           | `frontend/` |
| Backend  | NestJS + TypeScript, TypeORM, SQLite (file `backend/notes.sqlite`) | `backend/`  |

## Requirements

automatically on first start.

## Running the app

```bash
./start.sh
```

The script:

0. have been tested on Linux/WSL 
1. checks that Node.js (≥ 20.19) and npm are installed,
2. creates `backend/.env` and `frontend/.env` with defaults if they are missing
   (a random `JWT_SECRET` is generated),
3. installs the dependencies of both apps and builds the backend,
4. starts the backend and the frontend together and prints their URLs.

Press **Ctrl+C** to stop both.

| App      | URL                   |
| -------- | --------------------- |
| Frontend | http://localhost:5173 |
| Backend  | http://localhost:3000 |

**Default login:** `admin` / `admin123` (seeded on startup if it doesn't exist).

> If the scripts lost their executable bit (e.g. after copying the folder from
> Windows to Linux/WSL), run `chmod +x start.sh test.sh` or call them with `bash start.sh`.
>
> `node_modules` is platform-specific. `start.sh` records the platform it was
> installed on and automatically reinstalls dependencies when the folder is
> used from a different OS, CPU architecture or Node.js major version (e.g. a
> folder installed on Windows and then run from Linux/WSL). Under WSL, keep the
> project on the Linux filesystem (e.g. `~/notes`) rather than `/mnt/c`, which
> is much slower.

## Tests

```bash
./test.sh
```

Runs `./start.sh`, checks that both apps start without errors, exercises the
API with curl (login, notes CRUD, archiving, categories, filtering, validation,
auth errors), then stops and restarts the app to confirm the data persisted.
It uses a separate database (`backend/notes.test.sqlite`) that is deleted at the
end, so your own notes are never touched. Ports 3000 and 5173 must be free.

## Architecture

```
.
├── start.sh / test.sh
├── backend/                 NestJS REST API
│   └── src/
│       ├── main.ts          bootstrap: global ValidationPipe, CORS
│       ├── app.module.ts    config + TypeORM (SQLite, synchronize)
│       ├── common/          @CurrentUser decorator, shared types
│       ├── auth/            login controller, AuthService, JwtAuthGuard, DTOs
│       ├── users/           User entity, repository, service (+ admin seed)
│       ├── notes/           Note entity, controller, service, repository, DTOs
│       └── categories/      Category entity, controller, service, repository, DTOs
└── frontend/                React SPA (Vite)
    └── src/
        ├── config.ts        API base URL (VITE_API_URL)
        ├── api/             fetch client (adds the JWT, handles 401) + endpoints
        ├── pages/           LoginPage, NotesPage
        └── components/      NoteCard, NoteFormModal, CategoryManager, Modal, ConfirmDialog
```

The backend is organised by module (`auth`, `users`, `notes`, `categories`),
and each module follows the same layers:

- **Controllers** – map HTTP routes to service calls; no business logic.
- **Services** – all business rules: authentication, archiving, category
  assignment, filtering, ownership checks, error handling.
- **Repositories** – the only code that touches the database, through TypeORM
  repositories injected with `@InjectRepository`.
- **Entities** – `User`, `Note`, `Category`. `Note ↔ Category` is a
  `@ManyToMany` with a `@JoinTable` (`note_categories`). Notes and categories
  belong to a user.
- **DTOs** – every input (body, query, params) is validated with
  `class-validator` through a global `ValidationPipe` (unknown fields are
  rejected).

Passwords are hashed with bcrypt. All note and category endpoints require a
`Authorization: Bearer <token>` header (`JwtAuthGuard`). The frontend keeps the
token in `localStorage`, sends it on every request and returns to the login
screen on any `401` or when the user logs out.

## API

All endpoints except `POST /auth/login` require `Authorization: Bearer <token>`.

| Method | Path                                   | Description                                                   |
| ------ | -------------------------------------- | ------------------------------------------------------------- |
| POST   | `/auth/login`                          | `{ username, password }` → `{ accessToken, user }`            |
| GET    | `/notes?archived=true\|false&categoryId=<id>` | List notes (active by default), optionally by category |
| GET    | `/notes/:id`                           | Get one note                                                  |
| POST   | `/notes`                               | Create `{ title, content?, categoryIds? }`                    |
| PATCH  | `/notes/:id`                           | Update `{ title?, content?, categoryIds? }` (`categoryIds` replaces the set) |
| DELETE | `/notes/:id`                           | Delete a note                                                 |
| PATCH  | `/notes/:id/archive`                   | Archive a note                                                |
| PATCH  | `/notes/:id/unarchive`                 | Unarchive a note                                              |
| POST   | `/notes/:id/categories/:categoryId`    | Add a category to a note                                      |
| DELETE | `/notes/:id/categories/:categoryId`    | Remove a category from a note                                 |
| GET    | `/categories`                          | List categories                                               |
| POST   | `/categories`                          | Create `{ name }` (names are unique per user)                 |
| DELETE | `/categories/:id`                      | Delete a category (also removes it from its notes)            |

Notes are returned with their categories:

```json
{
  "id": 1,
  "title": "Meeting",
  "content": "Discuss roadmap",
  "archived": false,
  "createdAt": "2026-09-23T14:15:42.000Z",
  "updatedAt": "2026-09-23T14:15:42.000Z",
  "categories": [{ "id": 1, "name": "Work" }]
}
```
